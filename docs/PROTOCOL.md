# Протокол обмена между Go и C++

Go-часть запускает решатель как отдельный процесс и общается с ним через
стандартные потоки. Никаких сокетов, библиотек и JSON — только текст.

```
          stdin                            stdout
Go  ──────────────────▶  solver (C++)  ──────────────────▶  Go
      лабиринт                              путь
```

Это **контракт**: пока обе стороны его соблюдают, их можно писать и менять
независимо друг от друга.

## Вход (stdin)

Первая строка — ширина и высота, разделённые пробелом.
Далее ровно `height` строк по `width` символов:

| Символ | Значение |
|--------|----------|
| `#`    | стена, проходить нельзя |
| `.`    | свободная клетка |
| `S`    | старт (ровно один) |
| `G`    | цель (ровно одна) |

Пример:

```
5 3
#####
#S.G#
#####
```

Координаты — `x y`, где `x` — номер столбца, `y` — номер строки, нумерация
с нуля. В примере выше старт это `1 1`, цель — `3 1`.

Ходить можно на 4 стороны: вверх, вниз, влево, вправо. Диагоналей нет.

## Выход (stdout)

**Путь найден** — строка `OK <количество клеток>`, затем по одной клетке
на строку, от старта к цели включительно:

```
OK 3
1 1
2 1
3 1
```

Путь должен быть кратчайшим по числу клеток. Старт и цель входят в путь,
поэтому минимально возможный ответ — `OK 1` (когда `S` и `G` совпадают,
чего в наших лабиринтах не бывает) и `OK 2` для соседних клеток.

**Пути нет** — одна строка:

```
NO_PATH
```

Это не ошибка. Лабиринт корректен, просто цель недостижима. Код возврата `0`.

## Ошибки

Если вход некорректен (размеры не совпадают с сеткой, нет `S`, две `G`,
неизвестный символ), решатель пишет сообщение в **stderr** и завершается
с кодом возврата, **отличным от нуля**. В stdout при этом ничего не печатается.

Почему так: stdout — это результат, его читает программа. stderr — это для
человека. Если смешать, Go-часть попытается разобрать текст ошибки как путь.

## Проверить руками

```
./solver/solver < testdata/simple.txt
```

Эталонная реализация на Go доступна для сравнения:

```
go run ./cmd/maze -input testdata/simple.txt -solver reference -print-raw
```
