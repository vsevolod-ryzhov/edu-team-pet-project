# maze — поиск пути в лабиринте

Учебный проект на двух языках. Go-часть читает лабиринт, запускает решатель
и рисует результат. Решатель — отдельная программа на C++, которая получает
лабиринт в stdin и возвращает путь в stdout.

```
$ go run ./cmd/maze -input testdata/corner.txt
решатель: reference (Go, BFS)
длина пути: 11 клеток
#######
#S#***#
#*#*#*#
#***#G#
#######
```

## Начать здесь

Если ты пришёл по ссылке работать над C++-частью — тебе нужны три файла,
в этом порядке:

1. [`solver/README.md`](solver/README.md) — твоё задание и чеклист.
2. [`docs/PROTOCOL.md`](docs/PROTOCOL.md) — как твоя программа общается с Go.
3. [`docs/WORKFLOW.md`](docs/WORKFLOW.md) — как мы работаем с ветками и PR.

Остальное на этой странице — про проект в целом, читать не обязательно.

## Из чего состоит

| Путь | Чьё | Зачем |
|------|-----|-------|
| `cmd/maze/` | Go | командная строка |
| `internal/maze/` | Go | разбор лабиринта, отрисовка, проверка пути |
| `internal/solver/` | Go | запуск внешнего решателя и эталонный BFS |
| `solver/` | C++ | поиск пути — см. [`solver/README.md`](solver/README.md) |
| `docs/PROTOCOL.md` | общее | контракт между частями |
| `docs/WORKFLOW.md` | общее | ветки, коммиты, pull request, конфликты |
| `testdata/` | общее | лабиринты для проверки |

Главное в этой таблице — последние две строки. `docs/PROTOCOL.md` описывает,
как части договариваются между собой; пока контракт соблюдается, Go и C++
можно писать и менять независимо.

## Запуск

```
go run ./cmd/maze -input testdata/corner.txt                           # эталонный решатель на Go
go run ./cmd/maze -input testdata/corner.txt -solver ./solver/solver   # решатель на C++
cat testdata/simple.txt | go run ./cmd/maze                            # лабиринт из stdin
```

Флаги: `-input` (файл или `-` для stdin), `-solver` (`reference` либо путь
до бинаря), `-timeout` (сколько ждать внешний решатель), `-check` (проверять
корректность полученного пути; выключается для отладки).

Путь до решателя можно задать переменной окружения `MAZE_SOLVER`.

## Проверка

```
go test ./...                                   # все тесты
go test ./internal/solver/ -run TestDecodePath  # один тест
go vet ./...
gofmt -l .                                      # печатает файлы, которые надо переформатировать
```

## Docker

```
docker build -t maze .
docker run --rm maze                                  # лабиринт по умолчанию
docker run --rm maze -input /testdata/no_path.txt
cat testdata/simple.txt | docker run --rm -i maze -input -   # лабиринт из stdin
```

Обратите внимание на `-input -` в последней команде: без него сработает
аргумент по умолчанию из `CMD`, и программа прочитает файл, а не stdin.

Сборка многостадийная: компиляторы остаются в промежуточных стадиях,
в финальный образ попадает только готовый бинарь и `testdata/`.
